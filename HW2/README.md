# MIPT Finance App

## Описание проекта

Консольное приложение для учета финансов  

## Функциональность

1. Работа с доменной моделью:
   - Создание, редактирование и удаление банковских счетов, категорий, операций

2. Импорт данных:
   - Импорт данных из текстовых файлов формата CSV, YAML, JSON

## Применение принципов SOLID и GRASP

1. Single Responsibility Principle:
   - Каждый класс имеет только одну причину для изменения
   - Например, класс `CategoryFactory` отвечает только за создание категорий, а `CategoryRepository` - за взаимодействие с хранилищем категорий

2. Open/Closed Principle:
   - Расширение функциональности без изменения существующего кода
   - Например, новые импортеры для других форматов можно добавлять без изменения существующих классов

3. Liskov Substitution Principle:
   - Подтипы могут заменять базовые типы без нарушения работы программы
   - Все реализации `DataImporter` могут быть использованы в `ImporterComposite` без изменения его кода

4. Interface Segregation Principle:
   - Интерфейсы разделены на специфические части
   - Например, `Command` имеет только один необходимый метод `execute()`

5. Dependency Inversion Principle:
   - Зависимости инвертированы через внедрение зависимостей
   - Например, `OperationFactory`, `OperationRepository`, `BankAccountRepository` и `CategoryRepository` в `OperationFacade`
   - Использование Spring для внедрения зависимостей

6. GRASP: Low Coupling:
   - Минимальная зависимость между компонентами
   - Использование фасадов для инкапсуляции взаимодействия между компонентами

7. GRASP: High Cohesion:
   - Связанная функциональность сгруппирована вместе
   - Например, все операции с банковскими счетами находятся в `BankAccountFacade`

## Используемые паттерны проектирования GoF

### Порождающие

1. Фабрика (Factory):
   - `BankAccountFactory`, `CategoryFactory`, `OperationFactory`
   - Обеспечивает централизованное создание объектов с валидацией

2. Строитель (Builder):
   - `BankAccountBuilder`, `CategoryBuilder`, `OperationBuilder`
   - Позволяет создавать сложные объекты пошагово
   
### Структурные

3. Фасад (Facade):
   - `BankAccountFacade`, `CategoryFacade`, `OperationFacade`
   - Предоставляет простой интерфейс для работы со сложной подсистемой, содержащей множество классов

4. Компоновщик (Composite):
    - `ImporterComposite`
    - Позволяет создавать список объектов и работать с ним так же, как и с единичным объектом

5. Декоратор (Decorator):
    - `TimedCommandDecorator`
    - Позволяет динамически добавлять новую функциональность (измерение времени выполнения), оборачивая другие команды

### Поведенческие

6. Команда (Command):
   - `Command` с методом `execute()` и его реализации
   - Превращает запросы из консоли в объекты, позволяя передавать их как аргументы при вызове методов. 
   - Внутри себя обращаются к фасадам

7. Шаблонный метод (Template Method):
   - `DataImporter` с абстрактным методом `parseFile()` и его реализации
   - Определяет общую структуру алгоритма, позволяя наследникам переопределить определенные шаги

## Инструкции по запуску

1. Соберите проект в jar-файл с помощью Maven:

```bash
mvn clean package
```

Для удобства проверки это уже было сделано. Готовый jar находится в папке `target` проекта

2. Запустите полученный jar-файл с помощью JVM (Java 17+):

```bash
java -jar target/finance-app.jar
```

## Примеры использования

1. Импорт данных:
    - В меню выберите пункт "Import Data", затем выберите формат (JSON/YAML/CSV) и укажите путь к файлу или директории с файлами (для CSV)
    - Можете попробовать указать в качестве пути "./data.json", "./data.yaml" и "./data-csv"
   
2. Создание счетов и категорий:
   - В меню выберите пункт "Manage Bank Accounts", затем "Create Account", введите в консоль требуемые данные
   - В меню выберите пункт "Manage Categories", затем "Create Category", введите в консоль требуемые данные

3. Добавление операций:
   - В меню выберите пункт "Manage Operations", затем "Create Operation", введите в консоль требуемые данные
